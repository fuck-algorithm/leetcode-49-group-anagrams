# LeetCode 49 界面重设计记录

## 设计方案

- Palette: 石墨蓝 `#172638`、雾白 `#F5F8FA`、墨色 `#20313D`、算法青绿 `#16836F`、比较琥珀 `#D99A2B`、错误红 `#B94B4B`；禁止紫色。
- Typography: 系统中文无衬线；代码和索引使用系统等宽字体；让原词、排序签名、分组状态成为主焦点。
- Layout: 48px header、42px 输入行、剩余视口给画布与代码、48px 控制栏；宽屏画布/代码左右分栏，窄屏上下分区，不使用与 grid 冲突的定位抽屉。
- Visual principle: 一条算法轨迹“输入原词 → 排序签名 → Map 原词组”作为核心可视化，辅助控制保持紧凑。

## 根因

1. App 网格轨道与 Header/Input/Control 的真实高度不匹配：控制条原 CSS 最低约 74px，但外层只分配 44px，因而覆盖画布。
2. 窄屏代码栏仍要求至少 320px 网格列，却同时设置抽屉定位参数，造成挤压/溢出。
3. Canvas 以容器高度作为内容高度，滚动判断恒 false；SVG 三泳道内容因此落到 viewBox 外时会被裁切。
4. SVG viewport 没有依内容尺寸扩展，横向溢出也没有稳定滚动承载区。

## 本轮实现范围

修正固定行尺寸与各组件尺寸一致，控制栏重排为单行按钮/进度/步数；代码栏在 1100px 以下移至画布下方；Canvas 按真实内容大小设置 viewport/viewBox 并启用横纵滚动。工作区保留当前算法和题目说明功能。

## 验收要求

以 Playwright 逐档验证 1920x1080、1366x768、1024x768、390x844：无元素重叠、横向页面溢出或非预期整页纵滚；代码/画布不互相遮挡；SVG 真实内容包围盒可见。跑 lint、typecheck、build、单测及已存在的 E2E；本轮不因此宣称 AC-023 画布 keyed join 已完成。
